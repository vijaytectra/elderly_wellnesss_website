# Performance Optimization Report

Static HTML/CSS/vanilla-JS site. No framework migration; no redesign. All work
is in the existing codebase.

---

## 1. How these numbers were measured

Lighthouse 12, mobile preset, default (simulated) throttling — the same
configuration PageSpeed Insights lab data uses. Chrome 1xx headless.

**Measurement caveat, stated up front:** this machine ran a Next.js dev server,
jest, and ~30 Chrome processes throughout the session. Lighthouse's
`benchmarkIndex` — its measure of host speed — swung between **667 and 2414**
during the work, i.e. the host varied by more than 3x. Single Lighthouse runs
on this box vary by ±20 Performance points, so single-run numbers are not
trustworthy here.

Every before/after figure below therefore comes from **interleaved A/B runs**:
the original code is served from one port, the optimized code from another, and
runs alternate `A,B` / `B,A` so host drift hits both equally. Medians are
reported, with each pair's `benchmarkIndex` recorded to confirm the two builds
saw comparable hardware.

Both builds are served over the same compressing server (Brotli + cache
headers) so the comparison isolates **code** changes rather than server config.

Harness: `scripts/` plus a local measurement rig (interleaved runner, CLS
attribution probe, geometry-diff probe, 24-shot visual-regression differ).

## 3. Every issue found, with root cause

### 3.1 CLS 0.65 — the async-CSS race *(largest single defect)*

**Root cause.** The homepage inlined two large `<style>` blocks and loaded the
remaining six stylesheets with `media="print" onload="this.media='all'"`. Those
sheets therefore applied *after* first paint. Whatever the inline CSS did not
already specify re-laid-out the moment they landed, and the timing of that
landing varies with connection speed — which is why CLS measured anywhere from
0.03 to 1.44 across runs of identical code.

**Fix.** One render-blocking, purged, minified bundle per page. First paint now
equals final layout, deterministically, at any connection speed.

Files: `index.html`, all 13 content pages, `scripts/build-css-bundle.js`,
`scripts/purge-css-bundle.js`, `scripts/build-page-bundles.js`.

### 3.2 CLS — Owl carousels collapsing from 0px to full height

**Root cause.** `owl.carousel.min.css` ships `.owl-carousel{display:none}` and
Owl only reveals the element once its JS runs. Every carousel occupied 0px and
then snapped to full height, shoving the page down. On about.html that single
jump was 350px, worth 0.34 CLS on its own.

**Fix.** `css/ew-carousel-reserve.css`, generated by
`scripts/measure-carousel-heights.js`, which measures each carousel's real
initialised height per breakpoint in a headless browser and emits a `min-height`
that applies only while `:not(.owl-loaded)`.

*A first attempt reserved the space by revealing the first slide instead. That
corrupted Owl's `autoWidth` measurement and rendered `#about_slider` as two
rows — 700px instead of 350px. Caught by the visual-regression differ and
replaced with the measured approach.*

### 3.3 CLS — Owl's dots strip injected after init

Reserved up-front in the homepage critical CSS (380px → 415px jump removed).

### 3.4 LCP 4.3s — hero image trapped inside the carousel *(homepage)*

**Root cause.** The LCP `<img>` lived inside `#frmae_slider`. Owl re-parents its
children into `.owl-stage` on init, which re-renders the image and resets LCP to
carousel-init time. Ablation proved it: blocking `owl.carousel.min.js` +
`main.js` moved observed LCP from **6688ms to 936ms** — identical to FCP.

**Fix.** The poster now sits *outside* the carousel as a static layer behind the
slides (`index.html`, `.hero_poster`), so it paints at FCP and Owl never touches
it.

### 3.5 LCP 12–27s — unoptimized images *(inner pages)*

**Root cause.** The homepage had optimized assets under `images/opt/`, but the
inner pages still referenced originals: `process.png` alone was 353K, and
about.html pulled ~1.1MB of PNG/JPG. Individual files reached **1110K**.

**Fix.** `scripts/optimize-images.py` generated WebP for 72 images —
**28.1 MB saved** — and `scripts/apply-webp-sources.js` wrapped 70 `<img>` in
`<picture>` with the original as fallback. A `picture{display:contents}` rule
keeps the wrapper out of the layout tree so no existing CSS changes behaviour.
This took nursing-services LCP from **26.7s to 2.7s**.

### 3.6 TBT 609ms — main-thread work during load

| Change | Effect |
|---|---|
| Nine Owl carousels initialised at once (~400ms task) | now per-carousel via IntersectionObserver, with a staggered one-per-tick safety sweep |
| Hero carousel initialised during load | deferred behind `load` (the static poster is already painted) |
| 630KB of hero MP4 with `autoplay` | `preload="none"`, playback armed after `load` |
| Blog cards fetched + rendered during load (~120ms) | deferred to idle / on-approach |
| `blogContainer.innerHTML +=` inside a loop | built once and assigned once |
| Sticky-card layout pass at DOMContentLoaded | deferred out of the load window |
| 177K of CSS | purged to ~104K (homepage), ~73K avg elsewhere |

Result: **609ms → 43ms**.

### 3.7 IcoFont — 615K for 23 icons

`scripts/build-icon-subset.js` scans the markup for `icofont-*` classes, reads
each codepoint from the full stylesheet, and subsets the font with `pyftsubset`.

**525K → 3.4K** font, **90K → 1.4K** CSS.

### 3.8 Three 404s → Best Practices 100

`images/bigstar.png` and `images/footer_bg.png` were referenced by CSS but have
never existed in the repo (confirmed against full git history). `bigstar` was
repointed to the existing `smallStar.png`; the `footer_bg` rule already had a
background-color, so the image declaration was dropped.

### 3.9 Corrupted CSS

Two genuine defects in the source stylesheets, both pre-existing:

- `css/style.css` — a lost `@media` opener left a stray `}`, so a block of
  footer rules intended for ≥992px was applying at every breakpoint.
- `css/responsive.css` — an orphaned declaration block whose selector had been
  lost, followed by a duplicate rule.

Both were invisible to browsers (CSS error recovery discards them) but hard
parse errors for PostCSS, which blocked purging. Repaired without changing
rendered output — verified by pixel diff.

### 3.10 Accessibility 89 → 100

- Owl builds dots as `<button role="button">` with no text and arrows as
  `<button role="presentation">` (a role not allowed on `button`). Patched as
  each carousel initialises — `ewPatchOwlA11y()` in `js/main.js`.
- 21 icon-only links and 13 icon-only buttons had no accessible name.
- 9 `contact.html` inputs were labelled by `placeholder` only.
- `target="_blank"` links gained `rel="noopener"` (72).
- `elderly-wellness.html` heading skipped h1 → h3; fixed with `aria-level="2"`
  so the exposed level is correct **without** a visual change (retagging would
  have moved it from 20px/700 to 32px/500).

### 3.11 SEO 92 → 100

- **Wrong canonical on three service pages.** `nursing-`, `geriatric-` and
  `assisted-living-services` all declared
  `<link rel="canonical" href="physiotherapy-services-for-elders.html">` — they
  were telling Google to de-index them in favour of a different page. This is
  the highest-severity finding in the report and was pure copy-paste damage.
- Canonical added to 7 pages that had none; 2 relative ones made absolute.
- Meta descriptions added to the three `company/` legal pages.
- `link-text`: "Read more" carries the article title via a visually-hidden
  span. (`aria-label` does **not** satisfy this audit — Lighthouse reads
  `innerText`.)

## 4. Visual fidelity

24 full-page screenshots (12 pages x mobile 412px + desktop 1440px) captured
before any change and re-diffed after every significant step.

**Final state: every page pixel-identical or within 0.01%,** except regions
occupied by autoplaying carousels. That residual was proven to be phase noise,
not regression, by diffing two runs of *identical* code (same 5.4% delta), and
page heights match the original exactly on all pages.

## 5. Not done — and why

### Colour contrast (Accessibility 95–96 on 9 pages)

The brand teal `#2786a5` scores **4.16:1** on white, under the 4.5:1 AA
threshold for text below 18px.

Darkening the token ~7% to `#247d99` (4.70:1) was implemented and **measured to
lift affected pages to Accessibility 100** — then deliberately reverted. The
teal is also used for large filled areas, so the change moved 4–8% of pixels on
the service pages and **33% on contact.html**. That is a real brand change and
conflicts with the explicit "preserve branding, do not redesign" constraint, so
it is a decision for you rather than for me.

It is left commented in `css/ew-a11y.css` with instructions. Two options:

1. Uncomment the `:root` override and re-run `node scripts/build-page-bundles.js`.
2. Keep the colour exactly and raise the affected text to ≥18px (or ≥14px
   bold), which shifts it to the 3:1 large-text threshold.

### Console errors (Best Practices 93–96 on 2 pages)

`elderly-wellness.html` and `investors.html` reference ~14 images that **do not
exist and never have** — verified against the full git history and by direct
request. They carry a `.png.html` suffix, the signature of an HTTrack/wget site
mirror, and the surrounding copy is still Lorem Ipsum ("Why we are Uqnqiue").

Affected: `banavt1–3`, `play.png`, `app-feature1–6`, `why-elderly`,
`hero_image`, `unique_1–7`. Fixing this needs either the real assets or a
decision to delete those markup blocks — a content call, not a technical one.
`css/style.css:4097` references a missing `rounded-down.svg.html` too.

### `image-size-responsive` (Best Practices 96 on 7 pages)

Some images are still served larger than their display size. The WebP pass
capped width at 1600px but did not generate per-breakpoint `srcset`. Closing
this needs responsive variants per image — mechanical, but a further pass.

### FCP and Speed Index

FCP moved 0.88s → 1.07s on the homepage. That is the deliberate cost of making
CSS render-blocking, and it bought CLS 0.647 → 0.000 — a far better trade under
Lighthouse's weighting (CLS 25%, FCP 10%). Speed Index remains above the 2.0s
goal on some pages.

Both would improve by splitting the bundle into above-the-fold critical CSS
(inlined) plus a deferred remainder containing only below-the-fold rules —
safe for CLS because shifts outside the viewport are not counted. It was not
attempted because the earlier split-CSS arrangement is exactly what caused the
0.65 CLS, and getting it wrong is expensive.

## 7. Production deployment checklist

1. **`nginx -t` before reloading.** The config was verified structurally only —
   nginx was not available here.

2. **Brotli is inert until you install it.** The config includes
   `/etc/nginx/snippets/brotli.conf*` (the trailing `*` makes a missing file
   harmless). To enable:
   - `apt-get install libnginx-mod-brotli`
   - *then* create the snippet using the body in the config's comment block.
   - Order matters: creating the snippet **without** the module makes
     `nginx -t` fail. Fix is to delete the snippet.

3. **Bump the `?v=` on every deploy that changes a bundle.** Assets are served
   `max-age=31536000, immutable`; anything edited without a URL change will be
   stuck in browsers for a year.

4. **Rebuild artifacts if you touch sources.** They are generated, not
   hand-written:
   ```
   python scripts/optimize-images.py          # after adding images
   node scripts/build-icon-subset.js          # after adding icons
   node scripts/measure-carousel-heights.js http://localhost:PORT
   node scripts/build-page-bundles.js         # after any CSS/markup change
   ```
   `build-page-bundles.js` needs purgecss resolvable — `PURGECSS_PATH=<dir>`.

5. **Re-run Lighthouse on a quiet machine.** Numbers here were taken on a
   contended host; expect equal or better on idle hardware. Use several runs
   and take the median, never a single run.

6. **Decide on the two open items** in §5: the brand-teal contrast trade-off,
   and the missing images on `elderly-wellness.html` / `investors.html`.

7. Originals are retained beside every generated WebP, so `<picture>` fallback
   works and nothing 404s.
